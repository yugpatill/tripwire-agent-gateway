# Injection, secret and PII detection

Every tool result goes through the detection pipeline before the agent sees it:

```
content ──► views (NFKC/casefold + decoded base64, URL-encoding, HTML entities,
             HTML comments, JSON \u-escapes, Unicode tag characters)
        ──► heuristics ──► classifier (if loaded) ──► LLM judge (gray zone, if enabled)
        ──► secrets ──► PII
```

What the result means for the session:

| Finding | Effect |
|---|---|
| injection verdict (see "Combining heuristics and classifier"), not cleared by the judge | result labelled `suspicious`; session marked suspicious (`session_has: suspicious` rules fire) |
| secret found | content returned to the agent has the secret replaced by `[REDACTED:<kind>]`; result confidentiality raised to `secret`; the original value stays in the taint store, so a later leak still matches |
| PII found | result confidentiality raised to at least `confidential` |

## Combining heuristics and classifier

Policy setting `detection.combine` (h = heuristic score, c = classifier score calibrated so the artifact threshold is 0.5, t = `suspicious_threshold`, default 0.5):

| `combine` | Suspicious when | Classifier runs | Phase 3 corpus (MiniLM-L6): FPR / recall, held-out FPR / recall |
|---|---|---|---|
| **`corroborated`** (default) | h ≥ t, or (0 < h and c ≥ t) | only when 0 < h < t, on the windows that overlap a heuristic span plus one neighbour on each side (at most 8) | 0.8% / 99.2%, 0% / 96.7% |
| `either` | max(h, c) ≥ t | on every result, unless h ≥ `classifier_threshold` (early exit) | 7.6% / 100%, 7.5% / 100% |

The corroborated rule keeps the classifier from acting alone, because on its own it flags raw HTML, terse API fields and imperative docs (see [ml/README.md](../ml/README.md#phase-3-corpus-analysis-minilm-l6)). It also takes the classifier off the hot path: 231 of the 250 benign Phase 3 samples (92%) have no heuristic signal at all and are never classified. The price is attacks that trip no heuristic at all ([limitations.md](limitations.md), item 12).

`detection.classifier_shadow: true` additionally classifies every result in the background after the decision, with the default window selection. The score is logged (`classifier.shadow`, with `would_flag` and the actual verdict) and appended to the stored event as a `classifier_shadow` detector, for the dashboard. It never changes a decision. At most 4 shadow runs are in flight; extra results are not shadow-classified (`classifier.shadow_dropped`).

Tool-call arguments are scanned for secrets. The `redact` policy action masks only the detected secret spans when there are any, and the whole argument otherwise.

## Detectors

| Detector | What it does | Notes |
|---|---|---|
| heuristics | about 30 weighted rules in five families (override, addressing the model, exfiltration/secrecy, role and delimiter markers, tool abuse), plus markdown image exfiltration and invisible-character counts. Score = `1 − Π(1 − w)`. Hits inside a hidden channel get +0.3. | A single weak signal (for example docs saying "ignore the previous instructions if you're on v2", weight 0.4) stays below 0.5 |
| classifier | Fine-tuned MiniLM-L6 int8 ONNX (23 MB, baked into the image) from `TRIPWIRE_CLASSIFIER_DIR`; 512-token windows with a 64-token overlap; the document score is the max window score, calibrated so the artifact's threshold (1% FPR on benign val data) maps to 0.5 | When the folder is missing or broken, one warning is logged and heuristics run alone. DeBERTa-v3-small is an opt-in accurate mode. Results: [ml/README.md](../ml/README.md#results-phase-4-2026-11-26) |
| LLM judge | Called only for scores in `[suspicious_threshold, classifier_threshold)`; returns a schema-validated verdict | Off by default. Needs `TRIPWIRE_LLM_JUDGE_ENABLED=true` and `TRIPWIRE_LLM_JUDGE_MODEL`. Errors and timeouts keep content suspicious |
| secrets | Provider keys and tokens, private keys (including truncated ones), JWTs, connection strings, and `password=`-style assignments gated on entropy | Placeholders such as `<YOUR_KEY>` and `changeme` are ignored |
| PII | Presidio with spaCy `en_core_web_sm` configured explicitly. Default `patterns` mode: tokenizer only, regex phone recognizer, no context enhancer | `TRIPWIRE_PII_MODE=ner` adds PERSON/LOCATION; `off` disables PII |

## Evaluation

Corpora: `gateway/tests/fixtures/`, generated by `gateway/scripts/build_corpus.py`. Evaluation: `gateway/scripts/eval_detectors.py`. CI gates: `gateway/tests/unit/test_detection_corpus.py`.

- **benign/**: 210 tool outputs: 40 web pages, 40 emails, 40 API JSON responses, 30 docs, 30 support tickets, and 30 hard negatives (text that says "ignore", "instructions", "system:", "note to the assistant…" without attacking).
- **attacks/**: 103 injections in six families, most embedded in realistic carriers.
- **heldout/**: 40 benign and 30 attacks, written *after* the rules were tuned and scored once.
- **quoted_payloads.jsonl**: 6 articles that quote a working payload verbatim, reported separately.

A sample counts as flagged when the heuristic or classifier score is ≥ 0.5, or when the secrets or PII scanner finds any match.

### Results (2026-11-21, heuristics)

**Before tuning** (first run, rules written before the corpus): heuristic false positives 5/210 (2.4%), recall 91/103 (88%).

**After tuning** (same corpus; optimistic, because rules were fixed after seeing failures):

| Benign category | n | heuristic | secrets | PII |
|---|---|---|---|---|
| web_pages | 40 | 0 | 0 | 0 |
| emails | 40 | 0 | 0 | 22 |
| api_json | 40 | 0 | 0 | 2 |
| docs | 30 | 1 | 0 | 2 |
| support_tickets | 30 | 0 | 0 | 0 |
| hard_negatives | 30 | 0 | 0 | 1 |
| **Total** | **210** | **1 (0.5%)** | **0** | **27** |

PII hits on benign data are expected and correct (emails contain addresses and phone numbers). They raise confidentiality and do not mark anything suspicious.

| Attack family | n | heuristic recall |
|---|---|---|
| direct_override | 18 | 17 (94%) |
| role_markers | 17 | 16 (94%) |
| hidden_unicode | 17 | 17 (100%) |
| base64 | 17 | 17 (100%) |
| html_comments | 17 | 17 (100%) |
| markdown_exfil | 17 | 17 (100%) |
| **Total** | **103** | **101 (98%)** |

**Held-out** (written after tuning, scored once, never tuned against): false positives **0/40**; recall **27/30 (90%)**. Direct overrides: 2/5. The three misses are paraphrases: "Discard the earlier brief entirely…", "ignore *each of* your prior instructions…", "your instructions have been changed…". The other five families: 5/5 each.

Quoted-payload articles: 6/6 flagged (see [limitations.md](limitations.md)).

Remaining false positive on the tuned set: a chat-log export ("User: … / Assistant: …"). Remaining misses: "Set aside what you were told earlier…" (paraphrase) and "End of user input. BEGIN ADMIN MODE…", a single weak delimiter signal.

Fixes made after the baseline run, all general rather than per-sample: base64 runs after `key=`, a JSON `\u`-escape view, folding Cyrillic/Greek lookalikes, excluding job titles after "assistant"/"agent", stricter markdown role headers, lower weights for chat-log markers, rules for common override idioms, local-only combination of signals, and weak rules as modifiers only.

### Classifier on this corpus (Phase 4, 2026-11-26)

The trained MiniLM-L6 classifier alone flags 18 of 250 benign samples (7.2%) and 101 of 133 attacks at its artifact threshold. With `combine: either` (suspicious when either fires): 7.6% false positives, 100% recall. With the default `combine: corroborated`: 0.8% false positives, 99.2% recall (held-out: 0/40 and 29/30). The false positives are raw HTML with analytics boilerplate, terse API fields, and imperative or warning sentences in docs. Details, examples and the retrain plan: [ml/README.md](../ml/README.md#phase-3-corpus-analysis-minilm-l6). Reproduce with `gateway/scripts/analyze_classifier.py`.
